# Deploy AegisIQ to Render.com — one-click, free tier

> Live in ~15 minutes: a public HTTPS backend + a public HTTPS console,
> both on free `*.onrender.com` subdomains, from a single `render.yaml`
> Blueprint.
>
> **What you get:**
> - Backend  → `https://aegisiq-backend.onrender.com`
> - Console  → `https://aegisiq-frontend.onrender.com`  ← open this in a browser
> - Auto TLS, auto redeploy on every `git push`.

## What Claude prepared for you

Everything below is already in the repo:

- **`render.yaml`** at the repo root — the Blueprint that provisions both
  services, wires CORS between them, and auto-generates the secrets
  (`SECRET_KEY`, `DATA_ENCRYPTION_KEY`, `DEFAULT_ADMIN_PASSWORD`).
- **`backend/Dockerfile`** — already Render-compatible (creates
  `/app/data`, boots uvicorn on the `$PORT` Render assigns).
- **`frontend/`** — Vite static-site build, published from `dist/` with an
  SPA rewrite so refreshing on `/alerts/42` doesn't 404.

You do **three things**. That's it.

## Step 1 — Push the repo to GitHub

If it isn't already on GitHub:

```powershell
cd C:\Users\ASUS\Downloads\lightweight-siem
git init
git add .
git commit -m "AegisIQ v2.4.1 — ready to deploy"
```

Create a new empty repo at https://github.com/new (name it whatever, e.g.
`aegisiq`), then:

```powershell
git branch -M main
git remote add origin https://github.com/<your-user>/aegisiq.git
git push -u origin main
```

## Step 2 — Create a Render account (free, no credit card)

1. Go to https://render.com and click **Get started for free**.
2. Sign up with the same GitHub account (fastest — grants Render read
   access to the repo you just pushed).

## Step 3 — Deploy the Blueprint

1. In the Render dashboard: **New +**  →  **Blueprint**.
2. Pick the `aegisiq` repository. Render reads `render.yaml` and shows
   the two services it will create.
3. Click **Apply**.

Render now:
- builds the backend Docker image (`backend/Dockerfile`),
- builds the frontend bundle (`npm ci && npm run build`),
- issues both HTTPS certificates,
- boots both services.

First build takes ~10 minutes. Watch progress under **Events** on each
service.

## Log in

When both services show **Live**, open
`https://aegisiq-frontend.onrender.com`.

Username is `admin`. The password was **auto-generated by Render**:

1. Open the **aegisiq-backend** service in Render.
2. Go to **Environment** on the left.
3. Copy `DEFAULT_ADMIN_PASSWORD` — that's your password.

Change it immediately after first login (**Security** page in the console).

## What to know about the free tier (honest)

- **Cold start.** Free services spin down after ~15 min idle. The first
  request wakes them in ~30 s (subsequent requests are instant). For a
  demo this is fine; for a live monitoring workload use a paid plan.
- **Ephemeral disk.** Render's free container filesystem is reset on every
  restart/redeploy. SQLite lives inside the container, so **prior events
  and alerts are wiped** when the service restarts — a fresh admin user
  and the 8 detection rules are re-seeded automatically. For persistent
  data attach a Render **PostgreSQL** and set
  `DATABASE_URL=postgresql+psycopg://…` on the backend service (the code
  already supports Postgres — see `docs/STORAGE.md`).
- **Bandwidth.** 100 GB / month egress. Plenty for a demo/showcase.

## Adding a custom domain (optional)

1. Buy a domain (Cloudflare Registrar, Namecheap, Porkbun — ~$10/year).
2. In Render → the **aegisiq-frontend** service → **Settings → Custom
   Domain** → add `console.<yourdomain>` (or the apex).
3. Add the CNAME record Render shows you at your DNS provider.
4. Update the backend's `CORS_ORIGINS` env var to include the new URL,
   and set the frontend's `VITE_API_URL` (build-time) to the new backend
   URL if you also point a subdomain at the backend. Re-deploy both.

## Redeploy after code changes

Every `git push` to `main` triggers an auto-redeploy of both services
(the Blueprint sets `autoDeploy: true`). Watch under **Events**.

To roll back: **Events → Manual Deploy → Redeploy** with an older commit.

## Troubleshooting

| Symptom | Fix |
|---|---|
| Frontend loads but calls fail with CORS error | The backend's `CORS_ORIGINS` didn't pick up the frontend URL. Confirm both service names match `render.yaml`, or set `CORS_ORIGINS=https://<your-frontend>.onrender.com` manually in the backend's env panel. |
| Frontend build fails on `npm ci` | Make sure `frontend/package-lock.json` is committed (it is — but a `.gitignore` mistake could exclude it). |
| Backend logs `DATA_ENCRYPTION_KEY not set` | Render should have auto-generated one. Check the backend's Environment tab; if empty, generate manually (`openssl rand -hex 32`) and paste. |
| First request very slow | Cold start (see Free tier notes). Send one request to `/health` and the next one is instant. |
| `sqlite3.OperationalError: unable to open database file` | Unlikely — the Dockerfile creates `/app/data`. If it happens, exec into the service and `ls -la /app/data`. |
